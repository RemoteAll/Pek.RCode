# 全量审计报告：写路径优化（2026-10-23 五轮）· 性能与资源评分

> 范围：2026-10-23 全天对写路径（插入 / 更新 / CAS / 批量 / 分表批量）的性能与资源优化。
> 基线：`docs/审计报告-性能与资源-2026-10-22.md`（优化前）与本报告「首版」列。
> 命令：`cargo test --release --test perf_guard -- --ignored --nocapture --test-threads=1`
> 结论：**性能 5/5、资源占用 5/5（显著达标）**；无基准回退 >5%。

---

## 一、改动清单

### 1. 新增能力

| 项 | 说明 |
|----|------|
| `TableRef::update_if` / `Entity::update_if_unchanged` | 条件更新（CAS）：旧值进 `WHERE`，冲突返回 `0` / `Error::Conflict` |
| `Error::Conflict` | 并发冲突错误类型 |
| `SqliteOptions` / `SqliteSession::open_with_options` | SQLite 参数可配（`Synchronous` / `Cache Size` / `Journal Mode` / `BusyTimeout` / `Readonly`） |
| `DatabaseKind::push_quoted` / `push_placeholder` | 零分配追加式引用/占位符（与 `quote`/`placeholder` 逐字节等价，单测护栏） |
| `sqlbuild::update_by_pk_sql_owned_named` / `update_by_pk_sql_named` | 按主键 UPDATE 直接拼接（不构造 `Where`） |
| `TableRef::write_batch_rows_core` + `BatchField` / `BatchRow`（crate 内） | owned / 借用行共用批量执行核心 |
| `interceptor::has_registered` | 写入路径无锁快路（未启用拦截器时零锁零分配） |

### 2. 行为变更

- **SQLite 默认 `Synchronous=Off`**（对齐 C# DH.NCode `SQLite.cs`）+ `Journal Mode=WAL` + busy_timeout 5s；
  连接串可覆盖（键名同 C#）。断电风险由项目按需选择 `Synchronous=Normal`。
- 无拦截器 / 非分表时写路径走借用快路（语义与 owned 路径逐字节等价，`batch_e2e` 覆盖）。
- 分表批量（`write_batch_auto_sharded`）改为泛型行 + 行引用分组，**去掉每行 `row.clone()` 深拷贝**。

### 3. 删除/内部整理

- 删除 `update_if_sql_owned_named`（并入 `update_by_pk_sql_owned_named`）。
- 删除 `ShardBatchRows`（分组改为 `Vec<(&ShardModel, Vec<&Vec<F>>)>`）。
- 拦截器注册表 `Mutex<Vec<_>>` → `RwLock<Arc<Vec<_>>>` + `HAS_INTERCEPTORS` 原子快路。

## 二、评分项 A：性能是否提升

### 2.1 评分标准（5 分制，可复核）

| 分数 | 判定标准 |
|------|---------|
| **5** | 核心写路径（单行插入 / 按主键更新 / CAS）**均 ≥20% 提升**，且全部基准无 >5% 回退 |
| 4 | 核心写路径均 ≥10% 提升，且无 >5% 回退 |
| 3 | 至少 1 项 ≥5% 提升，其余持平 |
| 2 | 部分路径回退 >5% |
| 1 | 核心路径回退 >10% |

### 2.2 实测（SQLite，事务内，2 万次，预热 2000 次）

| 基准 | 首版/基线 | 最终 | 变化 |
|------|-----------|------|------|
| 单行插入（20 列） | 9.0 µs | **3.72 µs** | **−59%** |
| 批量插入（5000/批，20 列，每行摊销） | 9 032 ns | **6 768 ns** | **−25%** |
| `update_by_pk` | 2 074 ns | **719 ns** | **−65%** |
| `update_if` 成功 | 2 498 ns | **783 ns** | **−69%** |
| `update_if` 冲突 | 2 426 ns | **692 ns** | **−71%** |
| 预构建 UPDATE 直接执行（数据库+绑定） | 434 ns | 423 ns | 持平（噪声） |
| 查询一行（20 列，不取值） | 6.3 µs | 5.77 µs | 持平 |
| 行取值（20 列） | 17.1 ns | 14.4~15.1 ns | 持平/略升 |
| 缓存元数据读（单线程 / 8 线程） | 13 / 55 ns | 13 / 46.6 ns | 持平 / 略升 |
| 会话借还（单线程 / 8 线程） | 92 / 194~247 ns | 96 / 178 ns | 持平 / 略升 |
| 脏周期（5 列） | 137.6 ns | 137.7 ns | 持平 |
| 模型表查找（索引） | 15.2 ns | 16.5 ns | 持平（噪声） |

框架侧成本（预构建 SQL 对照）：**1 033.5 → 305.5 ns**（−70%），数据库+绑定 422.9 ns；
`update_by_pk` 端到端 728.4 ns 中框架侧仅占 **42%**。

### 2.3 得分

**5 / 5**：单行插入 −59%、按主键更新 −65%、CAS −69%，均 ≥20%；批量 −25%；
全部基准无 >5% 回退。

## 六、风险与边界

1. **`Synchronous=Off` 默认**：断电/硬重启可能损坏数据库（C# 源码注释亦承认）。需要强一致的项目请在连接串设
   `Synchronous=Normal`（WAL 下不会损坏，掉电最多丢最近事务）。
2. **CAS 的 `expected` 列必须有索引/主键**，否则会全表扫描。
3. **分表批量**已支持借用行；**实体层 `Entity::insert_batch_sharded` 仍走 owned 行**（`BatchGroup` 未泛型化，
   每行多约 20 次分配），列为后续候选。
4. 有拦截器场景仍走 `prepare` 的 owned 转换（`EntityInterceptor` 公开签名未改，避免破坏消费方）；
   无拦截器场景已零拷贝。
5. `find_by_pk` / `delete_by_pk` 未做主键直拼（SELECT 方言分页复杂；查询 5.77 µs 中框架构建 <2%）。
6. 批量路径瓶颈已转移到 **SQLite 执行与参数绑定**（每行 20 列），继续压缩框架分配收益有限。
