# 审计报告：表级 `ConnName` 分库路由（2026-10-23）

## 1. 背景与目标

C# `HlktechIoT.Data/Model.xml` 中部分表带表级 `ConnName`（如 `StandardData`/`DeviceHistory`/`DeviceProperty`/`DeviceService` → `ConnName="IoTData"`），
语义等价于 DH.NCode `EntityBuilder.Load` 写入的 `Meta.ConnName`：**该表所有读写走命名连接（独立库）**。

Pek.RCode 模型层此前已解析 `TableMeta.conn_name`，但**运行时没有任何使用点**（分库不生效）。
本次补齐"表级 ConnName → 目标连接"的解析与一站式会话入口，并附测试与兼容性评估。

> 注意：`Column.DataScale="time"` 在 C# 里**不是分表**（只是"时间序列大表"标记：`MaxCacheCount=0` + 生成按时间列的 Find 扩展）；
> 真正分表是 `DataScale="timeShard:yyyyMMdd[:yyyy]"`（`Meta.ShardPolicy`）。本报告不改变 `timeShard` 的既有权衡。

## 2. 改动清单

| 文件 | 改动 |
|---|---|
| `src/shards.rs` | 新增 `pub fn resolve_table_dal(table_conn, base_conn, base_dal) -> Result<Option<Arc<Dal>>>`：表级连接名解析。规则与既有 `resolve_shard_dal` 一致（已注册连接复用 / 未注册自动建 `{自动目录}/{连接名}.db` 并缓存），但**基准比较对象改为模型级连接名**（表级 ConnName 正是覆盖它）。 |
| `src/dal.rs` | 新增 `Dal::table_conn_dal(name) -> Result<Option<Arc<Dal>>>`（`None` = 同连接）；新增 `Dal::with_table_session(name, f)`：解析连接 → 打开会话 → 构造 `TableRef` → 执行闭包。 |
| `tests/connname_routing.rs` | 新增矩阵测试（单测试顺序执行，避免全局注册表/自动目录竞争）。 |

## 3. 与 C# 的对应关系

| C# | Pek.RCode |
|---|---|
| `Table.ConnName` → `Meta.ConnName` | `TableMeta.conn_name`（已解析） + `Dal::table_conn_dal` |
| `DAL.Create(connName)` 自动建库 | 未注册 → `{自动目录}/{连接名}.db`（SQLite，复用 `open_auto_sqlite`/`set_auto_db_dir`） |
| `Entity` 隐式按 Meta.ConnName 选连接 | `Dal::with_table_session(table, |dal, table, session| …)`（本库会话是显式参数，故以入口函数等价） |

## 4. 兼容性

- **纯新增 API**，未改动任何既有函数签名与行为；`resolve_table_dal` 与 `resolve_shard_dal` 平行共存。
- `sync_schema` 行为未变（仍按模型全量建表）：分库表需要在目标连接上各自 `sync_schema`（与 C# 每个 DAL 各自 `SyncSchema` 的用法一致）。
- 自动建库仍走既有 `set_auto_db_dir`/`Data` 默认目录，遵守 `validate_conn_name`（字母/数字/`-_.`）。

## 5. 验证

| 范围 | 结果 |
|---|---|
| `cargo test`（Pek.RCode 全量，默认特性） | **23 个测试目标全绿**（exit=0，无 FAILED） |
| `tests/connname_routing.rs::table_conn_name_routing_matrix` | 通过：`RemoteTable`（ConnName=IoTData）写入落到 `IoTData.db`（1 行），主库同名表 0 行；`LocalTable` 落主库 1 行；连接名与模型级同名时不切换 |
| HlktechIoT `hlktech-iot-core` `authoritative_csharp_model_keeps_conn_and_data_scale` | 通过：C# 权威模型（53 表）可解析，`StandardData.conn_name == "IoTData"`、`StandardData.Id.data_scale == "time"` 均不丢失；三张接入表无 ConnName |

## 6. 边界与风险

1. **会话显式模型**：Pek.RCode 的 `TableRef` 操作需要调用方传入 `session`，因此"自动选库"无法在 `table()` 内部静默完成——
   消费方需改用 `with_table_session`（或先 `table_conn_dal` 再自开会话）。这是与 C# 的唯一结构性差异。
2. **`sync_schema` 不按 ConnName 分流**：基础连接仍会为模型内全部分库表建表；真实建库请对目标连接单独同步。
   若后续需要"按 ConnName 自动分流建表"，建议作为独立改动并评估对现有消费方（Pek.RAgent/Pek.RPanlServer/Pek.RCard/DHDeploy）的影响。
3. **自动建库仅支持 SQLite 回退**（与既有分片逻辑一致）；生产分库请显式 `register_connection` 注入各库 `Dal`。
4. **未包含 `timeShard:` 自动分表路由**：仍使用既有显式 API（`query_sharded`/`insert_sharded`/`auto_shard` 等），
   如需等价 C# `Meta.ShardPolicy` 的透明路由，建议下一轮单独实施（改 `TableRef` CRUD 入口，影响面较大）。

## 7. 后续建议

1. `timeShard:` 透明分表（`insert/update/delete/select` 自动按策略选表）；
2. `sync_schema` 按 `ConnName` 分流（可选开关）；
3. 消费方迁移清单：HlktechIoT（`StandardData` 等）、其它用 `ConnName` 的模型（当前仅本模型存在该属性）。
