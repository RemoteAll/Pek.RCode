# 前端规范（用户级 · 按技术栈按需加载）

## 面板前端交互规范（用户偏好 · 全项目适用）

- **禁止浏览器原生 `alert` / `confirm` / `prompt`**。用户 2026-11-10 原话：**「我记得其他项目我都没有用这种改密码的方案了，你为什么每次帮我弄都是同样的搞法，你是从其他项目学不到积累不到吗？」**，随后要求：**「这个是不是该进全局用户指令，因为你每一个项目都会这样弄，每次都需要我提醒」**。原生弹窗硬伤：样式与面板脱节、不能密码框（口令明文回显）、不能就地校验、不能异步提交（校验/请求失败就得重填）、按钮文案不可控。
- **唯一范式（照抄，不要自创）**：`Pek.RPanlServer/web/index.html`（`dialogOpen` L3997 / `dialogClose` L4014 / `dlgOk` L4019 / `dlgConfirm(title,message,okLabel,danger)` L4037 / `dlgPrompt(title,message,opts)` L4040）+ 独立站 `Pek.RDbProxy/res/index.html`、`Pek.RAgent/web/index.html`、`Pek.RCard/web-admin/index.html`。
  - DOM：`#dlg-overlay.modal-mask` → `.modal-box` → `.modal-head` / `.modal-body` / `.modal-actions`；
  - `dlgConfirm` 返回 `Promise<Boolean>`、`dlgPrompt` 返回 `Promise<String|null>`（本项目 `Pek.Proxy` 另补 `dlgAlert(title,message)`），**调用方一律 `await`、所在函数改 `async`**；Promise executor 内不能 `await` → 用 `.then()`；
  - 能力：`validate` 就地校验（不关窗）、`onOk` 异步提交（防重复点击、失败保窗）、`danger` 红色主按钮。
- **层级必须高于业务弹窗**：通用对话框 z-index 要盖住页面上的业务弹窗（RPanlServer 10000 vs 9999），因为业务弹窗（如切库三态选择）里还要再弹确认。
- **密码类输入一律 `type=password`**：改密 / 重置口令 / 设置令牌禁止用 `prompt()`。
- **危险操作语义不能丢**：删除 / 覆盖 / 吊销 / 升级替换 → `danger=true`；不可逆操作（覆盖数据、删库、删账号）先确认、必要时二次确认；只显示一次的信息（Key / 一次性口令）→ `dlgAlert` + 复制按钮。
- **全量自查，不要只改用户指出的那一处**：用户贴一张截图说明用错了范式，意味着整个面板都要过一遍 —— `Select-String -Path res/app.js,web/*.js -Pattern 'alert\(|confirm\(|prompt\('`，一次改净（2026-11-10 `Pek.Proxy` 共 14 处：prompt×1、confirm×12、alert×1）。
- **做面板任何一块前先翻生态**（弹窗、表格分页、状态标签、复制、拖拽上传、Toast、Tab、空状态、深色主题变量）；配色 / 圆角 / 间距沿用各项目现有 `app.css`，**不另起一套主题**。
- **改完先 `node --check`**：`confirm(` → ` await dlgConfirm(` 这类机械替换极易补错括号（2026-11-10 本项目 14 处里有 10 处括号位置错），语法不过不谈实测。
- **验证口径**：浏览器实跑断言「原生弹窗调用 = 0」「弹窗标题 / 按钮文案 / 输入类型正确」「就地校验不关窗」「成功才关闭」「`pageerror` = 0」。

## 后台配置页规范（用户偏好 · 全项目适用）

- **新增 / 修改配置项必须走完整保存链路**：视图字段（`name="..."`）→ 控制器 Action 参数 → 赋值到对应 `Setting.Current` → `Save()`；只加页面字段不补保存逻辑＝假功能。用户 2026-11-03 原话：「系统配置页加了保存的实际逻辑没加吗？」
- **保存后必须回读验证**：重新进入配置页或重读配置，确认值已持久化；敏感项（令牌 / 密码）按约定不回显明文，留空＝保留原值（`if (!String.IsNullOrWhiteSpace(x)) Setting.Prop = x.Trim();`）。
- **字段与参数一一对应**：新增页面字段时，用脚本对比视图 `name="..."` 与 Action 参数，禁止出现「页面有、参数无」；删字段时同步删除保存赋值，避免残留写入。
- **参考实现先查全部分支**：见「源码依赖自动拉新」——实现可能只在 `origin/2.0` 等非默认分支，不能只搜当前工作区。
